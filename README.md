# Store Intelligence API

## Project Overview

Store Intelligence API is a retail store intelligence platform that turns CCTV analytics events into operational and customer journey insights.

The backend ingests structured events generated by computer vision systems, stores them in SQLite, and exposes analytics APIs for:

- CCTV analytics event ingestion
- Store metrics analytics
- Visitor session tracking
- Funnel analytics
- Conversion tracking
- Re-entry tracking
- Queue monitoring
- Anomaly detection
- Store health analytics

The project is designed as a production-style take-home challenge implementation using FastAPI, SQLAlchemy ORM, Pydantic, and Pytest.

## Features

- Idempotent event ingestion with deduplication by `event_id`
- Partial-success batch ingestion with per-event failure reporting
- SQLite persistence through SQLAlchemy 2.x ORM models
- Visitor session reconstruction from historical event streams
- Entry, exit, dwell, conversion, and re-entry session handling
- Store metrics including unique visitors, entries, exits, dwell time, queue joins, queue abandons, abandonment rate, conversion rate, and peak hour
- Funnel analytics for entered, engaged, queue, and converted visitors
- Queue status classification as `NORMAL`, `BUSY`, or `CONGESTED`
- Anomaly detection for long dwell time, queue congestion, traffic spikes, low conversion, and empty store periods
- OpenCV and YOLO-based detection pipeline with tracking, visitor IDs, zone analytics, event generation, and ingestion upload
- Streamlit dashboard for metrics, funnel, queue status, anomalies, and heatmap views
- Structured JSON logging for ingestion, metrics, funnel, session rebuild, queue, and anomaly endpoints
- Safe 404 and 500 response handling
- Test coverage for ingestion, metrics, funnel/session logic, anomaly detection, heatmaps, tracking, event generation, and pipeline-to-API flow

## Tech Stack

OpenCV, Ultralytics YOLOv8, and Streamlit are included for the current detection pipeline and dashboard.

## Architecture

The application uses a service-layer architecture:

- Route handlers stay thin and handle request/response concerns.
- Business logic lives in service classes.
- SQLAlchemy ORM is used for persistence and aggregate queries.
- Pydantic models define request and response contracts.
- Dependency injection provides request-scoped database sessions.

Core service classes:

- `EventIngestionService` handles validation, deduplication, idempotency, and batch persistence.
- `MetricsService` calculates store-level metrics from persisted events.
- `SessionService` rebuilds and updates visitor sessions and calculates funnel analytics.
- `AnomalyService` detects operational anomalies and queue status from events, sessions, and funnel analytics.

### app/

- `app/main.py` creates the FastAPI application, registers routers, and initializes the database on startup.
- `app/db.py` configures SQLite, SQLAlchemy engine, session factory, declarative base, dependency injection, and database initialization.
- `app/models.py` defines SQLAlchemy ORM models for events, visitor sessions, POS transactions, and anomalies.
- `app/schemas.py` defines shared Pydantic schemas and the `EventType` enum.
- `app/ingestion.py` exposes `POST /events/ingest` and implements the event ingestion service.
- `app/analytics_service.py` implements store metrics calculations.
- `app/metrics.py` exposes `GET /stores/{store_id}/metrics`.
- `app/session_service.py` implements session tracking, session rebuild, re-entry detection, and funnel calculations.
- `app/funnel.py` exposes `POST /sessions/rebuild` and `GET /stores/{store_id}/funnel`.
- `app/anomaly_service.py` implements anomaly detection and queue status calculations.
- `app/anomalies.py` exposes `GET /stores/{store_id}/anomalies` and `GET /stores/{store_id}/queue-status`.
- `app/heatmap_service.py` implements zone-level heatmap analytics.
- `app/heatmap.py` exposes `GET /stores/{store_id}/heatmap`.
- `app/health.py` exposes a simple health endpoint.

### pipeline/

- `pipeline/detect.py` loads video, extracts frames with OpenCV, runs YOLO person detection, and writes `detections.jsonl`.
- `pipeline/tracker.py` assigns stable track IDs within a pipeline run.
- `pipeline/emit.py` maps tracks to visitor IDs, resolves configured zones, and emits ingestion-compatible business events.
- `pipeline/ingestion_client.py` uploads generated events to `POST /events/ingest` in batches with retry handling.
- `pipeline/run_pipeline.py` runs detection, tracking, event generation, and upload as one command.
- `pipeline/zones.json` defines the default rectangular store zones.

### dashboard/

- `dashboard/dashboard.py` is a Streamlit dashboard that reads from the API and displays metrics, funnel data, queue status, anomalies, and heatmap results.

### tests/

- `tests/test_ingest.py` validates batch event ingestion, duplicates, invalid payload handling, and partial success.
- `tests/test_metrics.py` validates store metrics, date filtering, conversion rate, abandonment rate, peak hour, and dwell time.
- `tests/test_funnel.py` validates session creation, session closure, dwell accumulation, conversion tracking, re-entry handling, rebuild, funnel responses, and failure handling.
- `tests/test_anomalies.py` validates anomaly types, queue status states, 404 behavior, and 500 behavior.
- `tests/test_heatmap.py` validates heatmap analytics, multi-zone scoring, date filtering, 404 behavior, and 500 behavior.
- `tests/test_pipeline_detection.py` validates detection configuration and mocked JSONL output.
- `tests/test_tracker.py` validates centroid tracking behavior.
- `tests/test_event_generation.py` validates visitor IDs, zone events, billing queue events, and JSONL output.
- `tests/test_ingestion_client.py` validates pipeline upload batching and retry behavior.
- `tests/test_hardening_integration.py` validates generated pipeline events and a mocked video-to-analytics flow through ingestion, database persistence, session rebuild, and analytics.

### data/

- `data/events.jsonl` is reserved for emitted event logs from the vision pipeline.
- `data/.gitkeep` keeps the directory available in version control.
- `data/store.db` is created automatically by the application and ignored by Git.

## Setup Instructions

Create and activate a virtual environment:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

On macOS or Linux:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the application:

```bash
uvicorn app.main:app --reload
```

Open Swagger documentation:

```text
http://127.0.0.1:8000/docs
```

Run tests:

```bash
pytest
```

Run the dashboard:

```bash
streamlit run dashboard/dashboard.py
```

Run the end-to-end pipeline after the API is running:

```bash
python pipeline/run_pipeline.py --video path/to/video.mp4
```

The pipeline reads video frames, runs YOLO person detection, tracks visitors, emits business events, and uploads them to `POST /events/ingest`.

Run with Docker:

```bash
docker compose up --build
```

Optional environment configuration is documented in `.env.example`. Defaults work for local development; set `STORE_DB_PATH`, `STORE_API_URL`, or `PIPELINE_*` variables when paths or service URLs differ.

## API Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Root status message |
| `GET` | `/health`, `/health/` | Health check |
| `POST` | `/events/ingest` | Ingest CCTV analytics events |
| `GET` | `/stores/{store_id}/metrics` | Store metrics analytics |
| `POST` | `/sessions/rebuild` | Rebuild visitor sessions from events |
| `GET` | `/stores/{store_id}/funnel` | Customer journey funnel analytics |
| `GET` | `/stores/{store_id}/anomalies` | Store anomaly detection |
| `GET` | `/stores/{store_id}/queue-status` | Queue performance status |
| `GET` | `/stores/{store_id}/heatmap` | Zone-level heatmap analytics |

All analytics endpoints support optional `start_time` and `end_time` query parameters where applicable.

## End-to-End Flow

1. Start the API with `uvicorn app.main:app --reload`.
2. Run `python pipeline/run_pipeline.py --video path/to/video.mp4`.
3. The pipeline writes detection and event JSONL files under the configured output directory.
4. Generated events are uploaded to `POST /events/ingest`.
5. Run `POST /sessions/rebuild` for the store when funnel/session analytics need to reflect newly ingested history.
6. Query metrics, funnel, anomaly, queue, and heatmap endpoints or open the Streamlit dashboard.

